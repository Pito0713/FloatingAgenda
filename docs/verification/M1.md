## 本里程碑自行決定事項

1. **`AppSettings.swift` 提前到 M1 建立**（PLAN 放在 M2）：位置記憶與透明度都要 UserDefaults，M1 不可能沒有它。hidden ID 兩個 key 一併按 §5.5 定義好，M2／M5 直接取用。
2. **`Models.swift` 提前到 M1 建立**（PLAN 放在 M2）：snapshot 的 mock 資料與面板骨架都需要這組值型別，M2 的 AgendaStore 只要負責 EK→值型別的轉換。
3. **透明度不寫死 0.9**（PLAN M1 寫「先寫死 0.9 測試」）：改為直接接上 `AppSettings.opacity`，可用 `defaults write` 客觀驗證夾限，M5 只要補滑桿即可，不必回頭拆寫死值。
4. **預設位置用 `NSScreen.screens.first` 而非 `NSScreen.main`**：實測 `NSScreen.main`（目前有鍵盤焦點的螢幕）會把卡片丟到副螢幕（x=3300），與 PLAN §4.1「主螢幕右上角」不符。
5. **`PanelMetrics` 與 `PanelRootView` 放在 `PanelController.swift`**（PLAN 的檔案清單沒有它們）。
6. **M1 骨架整層 `.allowsHitTesting(false)`**，讓拖曳區吃得到所有點擊；M3／M4 加入可點的列時會改成只關掉純顯示文字。
7. **`HeaderView.swift` 提前到 M1**（PLAN 放在 M3），內容小且穩定。
8. **毛玻璃遮罩的 capInsets 取 2× 圓角半徑**：continuous 圓角曲線會延伸到半徑之外，cap 只取 1× 會在拉伸時把曲線尾端切掉產生折角。

## 過程中兩個測試腳本自身的瑕疵（非程式碼問題，記錄以免重犯）

1. 第一版位置探測用 `.optionAll` 又只取清單第一個視窗，會抓到 MenuBarExtra 的 260×89 視窗；
   且 `.optionAll` 含未顯示視窗，導致「`panelVisible=false` 仍看到視窗」的假陽性。
   修正：過濾 `layer == 3` ＋ 檢查 `kCGWindowIsOnscreen`。
2. 透明度測試假設 `pkill` 一定成功，但 `open` 遇到還活著的 app 只會啟動它、不會重啟，
   結果四個案例讀到的都是上一輪的實例（全是 alpha=1 的假陰性）。
   修正：改成每步斷言（等舊行程真的死、`defaults read-type` 確認寫入、確認拿到新 pid）。
3. 另有一次我在背景測試執行中同時 `rm -rf build`，把測試正在啟動的 app 刪掉；
   以及 `pkill -x FloatingAgenda` 把同名的 `--snapshot` 行程一起殺掉（exit 143）。
   → 驗證與建置不要並行跑。
