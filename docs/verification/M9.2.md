### 一個失敗的修法與最後的做法（HIGH 那一條）

**第一次的修法**：在切換時同步量出真實尺寸再擺位置——
`hostingView.layoutSubtreeIfNeeded()` ＋ `hostingView.fittingSize`。

**實測證明這個修法無效**：在真實視窗裡印出來的是

```
MEASURED mode=full      fitting=(0.0, 0.0)  provisional=(320.0, 200.0)
MEASURED mode=collapsed fitting=(0.0, 0.0)  provisional=(320.0, 200.0)
MEASURED mode=character fitting=(0.0, 0.0)  provisional=(80.0, 80.0)
```

`fittingSize` 恆為 `(0, 0)`，因為 `sizingOptions = []` 把 hosting view 的內建尺寸計算
整個關掉了——而那個設定是必要的（不設，它自己的約束會跟我們的 `setFrame` 打架）。
guard 每次都退回佔位尺寸，等於什麼都沒修。**若只靠讀碼會誤以為修好了。**

**最後的做法**：`lastKnownSize: [DisplayMode: NSSize]` 快取每個模式上次量到的真實尺寸，
切換時拿它當起始尺寸。第一次進某個模式仍用靜態佔位值，但那一次尺寸一定會改變，
`onGeometryChange` 必然觸發；之後每次切換都有真實值可用。

### ⚠️ 誠實揭露：這個快取目前沒有測試能證明它必要

把快取拿掉（一律用 `provisionalSize`），**181 條測試全部照樣通過**。
原因是 `setFrame(display: true)` 會同步觸發一次 layout，所以實測中每次切換
`onGeometryChange` 都會觸發並補上正確尺寸——codex 描述的失效情境我**重現不出來**。

保留快取的理由是契約而非實測：SwiftUI 並未保證「值未變時仍會回報」，
目前會觸發是實作細節。快取讓面板的尺寸**由構造保證正確**，成本是一個字典。
這與專案既有的作法一致（`commitCompletion` 裡那道 `pendingCompletion` 守衛同樣是
沒有覆蓋的縱深防禦）。若之後有人要精簡，這是可以拿掉的候選，但請先確認上述假設。

**「遷移改用 register」這條一開始沒被抓到**，查證後發現問題出在測試而非替身：
`InMemorySettingsStore` 忠實模擬了 `UserDefaults`——`object(forKey:)` 會回退到
registration domain，所以分不出「真的寫入」與「只是有後備值」。
補了 `persistedObject(forKey:)` 只看寫入層之後，三條遷移測試立刻抓到這個變異。
（真實的 `UserDefaults` 不會把 registration domain 寫進磁碟，用 `register` 做遷移
會讓使用者的收合狀態在下次啟動時消失。）

### 未能由機器驗證的項目（誠實揭露）

1. **分段控制的實際外觀與點擊**：`ImageRenderer` 畫不出 AppKit 控件 → 使用者驗收。
2. **選單開著時按卡片箭頭，分段控制會不會跟著變**：修法是讓 `PanelController` 成為
   `@Observable` 的單一擁有者，理論上成立，但要同時操作選單與卡片才驗得到。
3. **`lastKnownSize` 快取的必要性**：見上方揭露。
4. **角色模式的點擊穿透**：M9.2 的色塊加了 `allowsHitTesting(false)`，
   但「透明區域能不能點到後面的視窗」要實際用滑鼠試 → §7.2 第 2 項。

## 本里程碑自行決定事項

1. **`PanelRootView` 改成注入式**（計畫未規定）：`mode` 由 `PanelController` 傳入，
   不自己讀 `AppSettings`。這讓顯示模式只有一個擁有者，也符合 §5.6「View 層資料注入」的原則。
2. **`PanelController` 加 `@Observable`**：讓選單列能跟著卡片箭頭的切換更新。
3. **`restoreFrame` 現在一律做垂直夾限**。舊版刻意只夾水平，因為還原時高度是佔位值，
   依它夾限會把卡片推到錯的地方（M1 實測存 y=200 會變成 286）。
   現在起始尺寸來自 `lastKnownSize`，這個妥協不再需要。
4. **`PanelAnchor` 抽成獨立型別**而不是在 controller 裡寫兩套分支：錨點換算是
   本里程碑最容易寫錯的地方，抽出來才能用純函式測到「尺寸改變時錨點不動」。
5. **`isUsable` 的高度門檻改成 `min(40, 面板高度)`**：原本寫死 40，
   對 80pt 見方的角色面板仍成立，但寫死值會讓更小的內容永遠判為不可用。
6. **`showBubble` 與 `characterSkinID` 沒有在本里程碑加入**（§5.5 有列）：
   前者是 M9.4、後者是 M9.5 才會用到，提早加只會是沒有讀者的設定。
7. **角色模式的邊距取 8pt**：面板大小＝看得到的內容大小是點擊穿透的前提（§5.4），
   這 8pt 是留給 M9.3 角色自己畫的陰影用的。
