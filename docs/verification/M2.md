| 判定 | 發現 | 查證 | 修正 |
|------|------|------|------|
| **CONFIRMED** | `items(from:)` 隔離不實 | `AgendaStore` 標了 `@MainActor`，其 static 成員繼承隔離；但這個方法確實在 `fetchReminders` 的背景 queue 上執行。Swift 5 語言模式不強制檢查所以編譯器沒報，宣告與實際執行環境不符 | `items(from:)` 與 `reminderOrder` 改標 `nonisolated static`，讓宣告誠實（Swift 6 模式下也不會爆） |
| **CONFIRMED** | 世代編號漏遞增 | 讀碼確認兩個 `guard … return` 都在 `reminderGeneration += 1` 之前。情境：查詢 A 在飛 → 使用者隱藏全部清單 → 提前 return 設成空清單但世代未變 → A 的結果通過檢查把舊資料蓋回來 | `reminderGeneration += 1` 移到函式最開頭，任何提前 return 之前 |

   無法在本次 session 內模擬

## 本里程碑自行決定事項

1. **`CalendarInfo` 值型別**（PLAN 未列）：選單列篩選（M5）與 `--dump` 都要「ID＋名稱＋來源＋顏色＋是否隱藏」，統一成一個值型別。
2. **`visibleCalendars` 在「全部被隱藏」時回 `nil` 並直接給空結果**：EventKit 的 predicate 收到 `nil` calendars 會當成「查全部」，不擋掉會變成隱藏了反而全部跑出來。
3. **提醒查詢加世代編號**（PLAN 未提）：`fetchReminders` 是非同步的，連續 refresh 會有結果亂序回來的競態。
4. **非 UI 狀態標 `@ObservationIgnored`**，其中 `deinit` 要碰的三個再加 `nonisolated(unsafe)`：`@Observable` 會把普通儲存屬性變成經過 registrar 的計算屬性，導致 nonisolated 的 `deinit` 碰不到它們。
5. **行事曆列表排序用 `(來源, 名稱)`**：`--dump` 與之後選單列的分組都需要穩定順序。M5 做選單列時會改用 `localizedStandardCompare`，目前的 ASCII 排序會讓 `user-b@example.com` 排在 `iCloud` 前面。
6. **`--dump` 等提醒最多 5 秒**：`fetchReminders` 非同步，不等就會印出「尚未載入」。
7. **面板在 M2 就接上真實資料**（PLAN 把 UI 放在 M3／M4）：否則 M2 做完面板還在顯示假資料，等於沒接線。`--snapshot` 仍然用 mock。
8. **`WidgetView` 改吃 `SectionState` 而非陣列**：權限與失敗狀態必須能表達，M6 只要把純文字佔位換成 `PermissionPrompt` 即可。
