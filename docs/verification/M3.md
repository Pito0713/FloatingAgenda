### 深層連結實測（PLAN §5.6 要求回報）

**結論：`ical://ekevent/<eventIdentifier>?method=show&options=more` 在 macOS 27 可用。**

真實 eventIdentifier 取自 `--dump`：

```
AAAAAAAA-BBBB-CCCC-DDDD-000000000006:AAAAAAAA-BBBB-CCCC-DDDD-000000000007
```

| 測試 | 結果 |
|------|------|
| shell `open "ical://ekevent/<id>?method=show&options=more"` | ✅ `exit=0`，前景 App 變成 `Calendar` |
| `NSWorkspace.shared.open(url)`（App 內實際用的 API） | ✅ 回傳 `true`，前景 App 變成 `Calendar` |
| 不存在的 scheme `floatingagenda-nope://x` | ✅ 回傳 `false` → 證明 fallback 的判斷條件是有效的 |

**踩到的坑**：`eventIdentifier` 形如 `<UUID>:<UUID>`，而 `.urlPathAllowed` **會**把冒號編成 `%3A`
（原本以為不會）。實測確認可用的那次是送原始冒號，因此改用
`.urlPathAllowed.union(CharacterSet(charactersIn: ":"))`，讓程式送出的字串與已驗證可用的形式
逐字節一致；空白等真正需要編碼的字元仍會被編碼（實測 `abc def:ghi` → `abc%20def:ghi`）。

**未能驗證的部分**：Calendar 是否真的**跳到那一筆**行程，我看不到畫面（沒有螢幕錄製權限），
`NSWorkspace.open` 對「有沒有正確解析到該筆」不會回報。→ 使用者驗收第 9 項。
