### CPU（§7.1）：**先不通過，改了做法才通過**

計畫 §5.3 指定用 `TimelineView(.periodic(by: 0.25))` 驅動 4 fps，理由是
「不要用 `repeatForever` 的 SwiftUI 動畫，那會用螢幕更新率一直重繪」。
方向對，但實測 **`TimelineView` 也沒過 §7.1 的 2% 上限**：

| 做法 | 30 秒內的 CPU 時間 | 平均 |
|------|------------------|------|
| 完整模式（無動畫） | 0.01s | 0.03% |
| TimelineView 4 fps | 0.97s | **3.23%** ❌ |
| TimelineView 4 fps ＋ 拿掉位移 | — | 3.25% |
| TimelineView 4 fps ＋ 每格畫同一張圖 | 0.89s | 2.96% |
| TimelineView 1 fps | — | 0.05% |
| **NSView ＋ Timer 直接繪圖（最終）** | 0.11s / 0.12s | **0.36% / 0.40%** ✅ |

拿掉位移沒有差、每格畫同一張圖也沒有差、降到 1 fps 就幾乎歸零——
成本是 `TimelineView` 每秒 4 次讓 SwiftUI 重新求值整個視圖樹**本身**，
與畫什麼無關。§7.1 的 CPU 上限是硬性驗收條件，所以改由 `CharacterHostView`
（NSView）直接繪圖：計時器只做 `setNeedsDisplay`，`draw(_:)` 把一張 16×16 的
CGImage 以最近鄰放大。**這是與計畫 §5.3 的刻意偏離，理由是實測數據。**

`ps -o %cpu` 一開始量到 3.4%，但 `sample` 顯示行程幾乎閒置——因為 `%cpu`
是衰減平均。全部改用 `ps -o cputime=` 的差值（累積 CPU 時間 ÷ 實際經過時間），
這個沒有歧義。

### 動畫真的在跑（低 CPU 不代表功能正常）

CPU 降下來之後必須確認不是「動畫根本沒動」。在 `draw(_:)` 暫時加 log，
實測 6 秒：

```
繪圖次數 24              → 4 fps ✅
tick 每次 +1             → 沒有跳格 ✅
眼睛列出現兩種            → 眨眼有發生 ✅
  .DBWKBBBBBBKWBD.（睜眼）／.DBKKBBBBBBKKBD.（閉眼）
位移出現 -4 / 0 / +4      → 動作有發生 ✅
```

位移是 −4/+4 交替而非彈跳，因為 probe 用的 bundle 沒有行事曆權限但讀得到專案，
其中一個專案卡住 → 判定為 `worried`，而 worried 的動作是抖動。判定正確。

   （前提斷言「第 0 格確實是眨眼點」，否則那條測試沒有鑑別力）。
2. **腳看不見**：腳原本用外框色，在深色背景上與背景融成一片。改用陰影色

## 內建角色的設計說明（§5.3 的版權底線）

皮膚 ID `builtin.pixel`，名稱「小方」。造型是一隻有**兩隻方耳朵**、
**兩條分開的短腿**、帶**腮紅**與**會變的嘴型**的圓身小生物。

與計畫點名不得照抄的角色的區別：

| 角色 | 它的特徵 | 小方的差異 |
|------|---------|-----------|
| Pac-Man 的鬼 | 圓頂無耳、底部是連續的波浪裙、只有眼睛、沒有嘴巴與腮紅 | 有方耳朵、底部是兩條分開的腿、有嘴巴與腮紅 |

## 未能由機器驗證的項目（誠實揭露）

1. **點擊、拖曳、右鍵在真實滑鼠下的手感**：3pt 門檻的判定有單元測試，
   但「拖得動」「點得到」「右鍵跳得出選單」只有實際操作才知道 → §7.2 第 1、2 項。
2. **點擊小精靈的行為**：M9.3 刻意**不接**——展開成卡片是 M9.4 的範圍，
   做一半的展開比沒有展開更讓人困惑。右鍵選單因此也還沒有「展開」這一項。
3. **「減少動態效果」的實際效果**：讀的是 `NSWorkspace.accessibilityDisplayShouldReduceMotion`，
   要在系統設定實際打開才驗得到 → §7.2 第 8 項。
4. **睡眠／鎖定時暫停**：要真的讓螢幕睡著才驗得到。目前有程式碼審查、
   codex 獨立審查（並抓到共用布林值的問題）、以及「計時器生命週期」的單元測試。
5. **深色桌面上的實際觀感**：snapshot 用的是不透明底色，真實面板是透明的。

## 本里程碑自行決定事項

1. **動畫改用 NSView ＋ Timer，不用計畫指定的 `TimelineView`**。理由是實測 CPU，
   數據見上。§7.1 的上限是硬性條件，§5.3 的手段是為了達成它。
2. **拆成三層**：`CharacterAnimation`（純計算，可測）、`CharacterHostView`
   （正式 App 的繪圖與滑鼠）、`CharacterView`（只給 `--snapshot` 的純 SwiftUI 靜態版）。
   最後一層是必要的——`ImageRenderer` 畫不出 `NSViewRepresentable`（M5 記錄過同一個限制）。
3. **眨眼用固定的間隔循環表**（12/17/14/20/15/13/18/16 格，總長 125 格）而不是亂數：
   同一個 tick 永遠得到同一個答案，畫面不會因為重繪而閃動，測試也能重現，
   而且間隔由表保證落在 3–5 秒內。第一版用 `tick % (12 + hash)` 算，實測會跑出
   7 格與 26 格的間隔。
4. **CGImage 快取以「心情 ＋ 格子內容」為 key**：格子資料是固定的，
   總量有上限（4 種心情 × 3 格），不會無限成長。
5. **`sleepy` 給 2 格而不是計畫允許的 1 格**：z 的高度變化讓「睡著」看得出來還活著。
6. **腳用陰影色而非外框色**：外框色在深色桌面上會與背景融成一片。
7. **右鍵選單先不放「展開」**：見上方揭露第 2 點。
