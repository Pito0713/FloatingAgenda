## Gate 0 紅線稽核（本里程碑最重要的一項）

PLAN §8 禁止在開發與驗證過程中寫入使用者的行事曆或提醒。M4 必須寫出勾選功能，
所以做法是：**寫出程式碼，但不執行它**，並用結構設計讓誤觸變成不可能。

### 寫入點只有一處

```

```

### 到達寫入點的路徑只有一條

```
$ grep -rn "commitCompletion" Sources/
AgendaStore.swift:253：self?.commitCompletion(id)          ← 唯一呼叫端（1.2 秒 Task 內）
AgendaStore.swift:259：private func commitCompletion(...)   ← private
```

`commitCompletion` 是 private，唯一呼叫端是 `toggleCompletion` 裡那個 1.2 秒後才執行、
且 `Task.isCancelled` 會擋下的 Task。

### View 層結構上不可能寫入

`RemindersSection` 與 `WidgetView` **完全不認識 `AgendaStore`**，勾選與開啟都是注入的 closure：

| 呼叫端 | 傳入的實作 |
|--------|-----------|
| `PanelController`（App 內） | `{ store.toggleCompletion($0) }` |
| `DevSnapshot`（`--snapshot`） | 不傳 → 用 `WidgetView` 的預設 `{ _ in }` 空實作 |

→ `--snapshot` 即使渲染「勾選中」的樣子，也**沒有任何程式碼路徑可以寫入**。

## 本里程碑自行決定事項

1. **勾選與開啟改用 closure 注入**（PLAN 未規定）：原因見 Gate 0——讓 `--snapshot` 在結構上不可能寫入使用者資料，而不是靠「記得不要呼叫」。
2. **寫入成功後刻意保留 `pendingCompletion`**：等 `.EKEventStoreChanged` 觸發 refresh 時才由
   `formIntersection` 清掉。若寫入後立刻移除標記，refresh 到達前會有一瞬間勾選狀態閃回未完成。
3. **`refresh` 時用 `pendingCompletion.formIntersection(ids)`** 清掉已不在清單中的標記，
   避免已完成或被外部刪除的提醒讓 Set 無限累積。
4. **寫入失敗時把狀態設成 `.failed` 並移除 pending**：讓使用者看得到失敗原因，而不是卡在勾選中。
5. **圓圈用 `inset.filled.circle` 而非 `largecircle.fill.circle`**：後者的填滿範圍太大，與原生提醒事項的勾選外觀差距較明顯。
6. **提醒列 hover 用 `Color.primary.opacity(0.06)`**：提醒列沒有像行程列那樣的底色可以加深，所以改用中性的淡底色。
7. **`Formatting.reminderDueLabel` 與 `Formatting.isOverdue` 移到 `Formatting`**：M2 那版逾期判定寫在 View 裡，M4 兩處都要用，集中到一處避免規則分歧。
8. **「還有 N 項」縮排 30pt** 與提醒標題（圓圈寬度 ＋ 間距）對齊。
