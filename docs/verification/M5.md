### 兩個 ImageRenderer 限制（都是渲染器問題，不是產品缺陷）

1. **`ScrollView` 的內容畫不出來**：第一版 menu snapshot 的篩選區整塊空白，連區段標題與
   「（沒有可用的項目）」都沒出現。判斷依據：我傳的是非空 mock，若是資料問題也該顯示
   空狀態文字，連標題一起消失只能是 ScrollView 沒被渲染。
   → 加了只供 snapshot 用的 `scrollable` 參數，`false` 時攤平渲染。修正後內容全部正常出現，
   確認原本是渲染器限制。
2. **深色模式整份無文字**：`MenuBarView` 自己沒有背景（實際 App 由 MenuBarExtra 的系統彈出
   視窗提供），snapshot 沒有那層 → 深色模式的白字畫在透明底上。
   → 在 `DevSnapshot` 補 `.background(Color(nsColor: .windowBackgroundColor))`，
   **只動 snapshot 端不動產品程式碼**。修正後深色版正常。
3. `Toggle(.switch)` 渲染成黃色 🚫 佔位：`ImageRenderer` 畫不出 AppKit 的 switch 控件。
   篩選區的 `.checkbox` 樣式則正常渲染。

### 未能由機器驗證的項目（誠實揭露）

1. **實際點擊選單**：切換 Toggle、拖曳滑桿、勾掉某個行事曆後卡片是否立刻變化 → 使用者驗收第 5、6 項。
2. **`ScrollView` 的 320pt 高度上限**：snapshot 為了渲染而攤平，沒有經過 ScrollView 這條路徑。
   使用者有 14 個行事曆 ＋ 3 個清單，實際開選單就會知道有沒有正確捲動。
3. **`.switch` 樣式的 Toggle 外觀**：渲染器畫不出來。
4. **選單重新打開後狀態是否正確**：修正後 getter 直接讀設定，理論上不可能過期，但沒有實際開關選單驗證過。

## 本里程碑自行決定事項

1. **`MenuBarView` 的資料改成注入**（PLAN 未規定）：唯一能在沒有螢幕錄製權限下驗證選單外觀的方法，
   同時讓 `FloatingAgendaApp` 的 scene body 讀取 store → Observation 追蹤，清單變動時選單會更新。
2. **新增只供 snapshot 用的 `scrollable` 參數**：理由見上方限制 1。產品路徑預設 `true`，行為不變。
3. **`delegate` 改成 optional**：snapshot 傳 `nil`，沒有面板可操作。
4. **篩選切換寫在 `AgendaStore`**（`setCalendarHidden` / `setReminderListHidden`）而非直接在 View 改設定：
   把「寫設定」與「立刻重讀」綁在一起，避免呼叫端忘記 refresh。
5. **分組與來源排序都用 `localizedStandardCompare`**：M2 的 `--dump` 用 ASCII 序會讓
   `user-b@example.com` 排在 `iCloud` 前面，選單不沿用那個排法。
6. **只有一個來源時不顯示來源標籤**：避免 3 個清單上面掛一個沒有區分作用的「iCloud」標題。
7. **選單寬度從 260 改成 280**：行事曆名稱加上色點與勾選框後 260 會擠。
